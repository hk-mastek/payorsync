Build an advanced Contract Management Module for PayorSync with AI-powered clause library and intelligent contract drafting capabilities:

═══════════════════════════════════════════════════════════════════════════════
PART 1: CORE ARCHITECTURE & TECH STACK
═══════════════════════════════════════════════════════════════════════════════

BACKEND STACK:
- Python 3.11+ with FastAPI framework
- PostgreSQL 15+ for relational data (contracts, workflows, audit trails)
- Vector Database: Pinecone, Weaviate, or pgvector extension for semantic clause search
- LangChain framework for RAG implementation
- OpenAI GPT-4 or Anthropic Claude API for AI-powered clause suggestions
- Sentence Transformers (e.g., all-MiniLM-L6-v2) for embedding generation
- Redis for caching frequently accessed clauses and templates
- Celery for background tasks (embedding generation, bulk operations)

FRONTEND STACK:
- React 18+ with TypeScript
- TanStack Query (React Query) for server state management
- Zustand or Redux Toolkit for client state
- Lexical or TipTap rich text editor for contract drafting
- React Beautiful DnD for drag-and-drop clause arrangement
- Tailwind CSS + shadcn/ui components
- React Flow for visual workflow representation

CREATE COMPREHENSIVE SCHEMA:

1. CLAUSE LIBRARY TABLES:

   clause_categories (
     id UUID PRIMARY KEY,
     category_name VARCHAR(200) UNIQUE NOT NULL, -- 'reimbursement methodology', 'timely filing', etc.
     parent_category_id UUID REFERENCES clause_categories(id),
     description TEXT,
     display_order INTEGER,
     is_active BOOLEAN DEFAULT true,
     created_at TIMESTAMP,
     updated_at TIMESTAMP
   )
   -- Index: category_name, parent_category_id

   clause_templates (
     id UUID PRIMARY KEY,
     clause_code VARCHAR(50) UNIQUE NOT NULL, -- 'ESRD-BUNDLE-145', 'EPO-ASP-PLUS6'
     clause_title VARCHAR(500) NOT NULL,
     clause_text TEXT NOT NULL,
     clause_version VARCHAR(20) NOT NULL, -- Semantic versioning: 1.0.0
     category_id UUID REFERENCES clause_categories(id),
     
     -- Metadata
     payor_types TEXT[], -- ['commercial', 'medicare_advantage', 'managed_medicaid']
     jurisdictions TEXT[], -- ['federal', 'CA', 'TX', 'FL']
     service_types TEXT[], -- ['dialysis', 'pharmacy', 'physician']
     effective_date DATE,
     expiration_date DATE,
     
     -- Legal approval workflow
     status VARCHAR(50) DEFAULT 'draft', -- draft, pending_review, legal_approved, active, deprecated, archived
     created_by UUID REFERENCES users(id),
     approved_by UUID REFERENCES users(id),
     approved_at TIMESTAMP,
     
     -- AI/RAG features
     embedding_vector VECTOR(384), -- For pgvector, adjust dimension based on model
     usage_count INTEGER DEFAULT 0,
     last_used_at TIMESTAMP,
     
     -- Compliance & tags
     regulatory_references TEXT[], -- ['42 CFR 405', 'Medicare Manual Chapter 8']
     compliance_notes TEXT,
     tags TEXT[], -- ['bundled_payment', 'drug_pricing', 'esrd']
     
     -- Version control
     is_current_version BOOLEAN DEFAULT true,
     previous_version_id UUID REFERENCES clause_templates(id),
     change_summary TEXT,
     
     created_at TIMESTAMP DEFAULT NOW(),
     updated_at TIMESTAMP DEFAULT NOW()
   )
   -- Indexes: clause_code, category_id, status, payor_types (GIN), jurisdictions (GIN)
   -- Vector index: embedding_vector USING ivfflat or hnsw

   clause_variables (
     id UUID PRIMARY KEY,
     clause_id UUID REFERENCES clause_templates(id),
     variable_name VARCHAR(100) NOT NULL, -- {{REIMBURSEMENT_RATE}}, {{FILING_DAYS}}
     variable_type VARCHAR(50), -- 'percentage', 'currency', 'days', 'text'
     default_value TEXT,
     validation_rules JSONB, -- {"min": 100, "max": 200, "type": "percentage"}

   clause_relationships (
     id UUID PRIMARY KEY,
     parent_clause_id UUID REFERENCES clause_templates(id),

   -- Unique constraint: (parent_clause_id, child_clause_id, relationship_type)

PART 3: RAG-BASED AI IMPLEMENTATION
═══════════════════════════════════════════════════════════════════════════════

IMPLEMENT INTELLIGENT CLAUSE RETRIEVAL SYSTEM:

1. EMBEDDING GENERATION PIPELINE:

   File: services/embedding_service.py
   
   Functions:
   - generate_clause_embedding(clause_text: str) -> List[float]
     * Use sentence-transformers model: 'all-MiniLM-L6-v2' or 'all-mpnet-base-v2'
     * Normalize embeddings for cosine similarity
     * Cache embeddings in Redis with 24hr TTL
   
   - batch_generate_embeddings(clause_ids: List[UUID])
     * Process in batches of 50
     * Update clause_templates.embedding_vector
     * Handle failures gracefully with retry logic
   
   - regenerate_all_embeddings()
     * Background task for reprocessing entire library
     * Progress tracking and reporting
     * Versioned embeddings for A/B testing different models

2. SEMANTIC SEARCH ENGINE:

   File: services/clause_search_service.py
   
   Class: ClauseSearchEngine
   
   Methods:
   - semantic_search(query: str, filters: dict, top_k: int = 10) -> List[ClauseResult]
     * Generate query embedding
     * Perform vector similarity search
     * Apply filters: payor_type, jurisdiction, category, status='legal_approved'
     * Rerank results using cross-encoder for improved relevance
     * Return with similarity scores and rationale
   
   - hybrid_search(query: str, filters: dict) -> List[ClauseResult]
     * Combine semantic search with traditional keyword search (PostgreSQL full-text)
     * Use reciprocal rank fusion to merge results
     * Weight: 70% semantic + 30% keyword
   
   - contextual_clause_suggestions(context: ContractContext) -> List[ClauseResult]
     * Input: contract_type, payor_type, jurisdiction, current_section, existing_clauses
     * Build context-aware query from contract metadata
     * Filter out already-selected clauses
     * Apply business rules (e.g., mandatory clauses for Medicare contracts)
     * Check for clause conflicts using clause_relationships table
     * Return ranked suggestions with explanations

3. RAG IMPLEMENTATION:

   File: services/rag_service.py
   
   Class: ContractDraftingRAG
   
   Methods:
   - get_intelligent_suggestions(
       contract_context: dict,
       user_query: Optional[str] = None,
       section: Optional[str] = None
     ) -> dict
     
     ALGORITHM:
     Step 1: Context Understanding
       - Extract: payor type, jurisdiction, service category, contract model
       - Identify current drafting stage and incomplete sections
     
     Step 2: Retrieval
       - If user_query provided: semantic search on query
       - If section provided: retrieve clauses commonly used in that section for this contract type
       - Apply mandatory clause rules
       - Retrieve related clauses based on existing selections
     
     Step 3: Filtering & Ranking
       - Jurisdictional compliance check
       - Payor-specific preferences
       - Historical usage patterns for similar contracts
       - Conflict detection with existing clauses
       - Scoring: (semantic_similarity * 0.4) + (usage_frequency * 0.2) + (recency * 0.1) + (compliance_match * 0.3)
     
     Step 4: Augmentation (LLM-powered insights)
       - Send top 5 clauses + contract context to Claude/GPT-4
       - Prompt: "Given this contract context and these clause options, explain which clauses are most appropriate and why. Consider compliance, standard practices, and payor preferences."
       - Return AI-generated rationale for each suggestion
     
     Step 5: Return structured response:
     {
       "suggested_clauses": [
         {
           "clause_id": "uuid",
           "clause_code": "ESRD-BUNDLE-145",
           "clause_title": "ESRD Bundled Payment Rate",
           "clause_text": "...",
           "similarity_score": 0.92,
           "ai_rationale": "This clause is highly recommended for commercial dialysis contracts...",
           "category": "reimbursement methodology",
           "usage_count": 247,
           "last_used_with_similar_contracts": "2024-12-15"
         }
       ],
       "mandatory_clauses": [...],
       "complementary_clauses": [...],
       "conflicting_clauses_to_avoid": [...]
     }

   - draft_clause_text(
       clause_template_id: UUID,
       variable_values: dict,
       customization_instructions: Optional[str] = None
     ) -> str
     
     * Fetch clause template
     * Replace variables: {{REIMBURSEMENT_RATE}} → actual value
     * If customization requested, use LLM to modify clause while maintaining legal integrity
     * Track customizations in contract_clauses.customized_text

   - validate_clause_compatibility(
       contract_id: UUID,
       new_clause_id: UUID
     ) -> ValidationResult
     
     * Check clause_relationships for conflicts
     * Verify no duplicate clauses covering same topic
     * Ensure all prerequisite clauses are present
     * Return warnings/errors

4. CONTEXT-AWARE AUTOCOMPLETE:

   File: services/autocomplete_service.py
   
   - suggest_next_clause(contract_id: UUID, current_position: str) -> List[Clause]
     * Analyze contract structure progression
     * Identify missing standard clauses
     * Suggest next logical clause based on template flow
     * Learn from analyst patterns (if they always add X after Y, suggest it)

PART 4: WORKFLOW ENGINE
═══════════════════════════════════════════════════════════════════════════════

IMPLEMENT APPROVAL WORKFLOW SYSTEM:

File: services/workflow_service.py

Class: WorkflowEngine

Methods:
- initiate_clause_approval(clause_id: UUID, requested_by: UUID) -> UUID
  * Create approval_request record
  * Determine workflow based on clause category and impact
  * Notify first approver(s)
  * Return request_id

- process_approval_action(
    request_id: UUID,
    approver_id: UUID,
    action: str,  # 'approved', 'rejected', 'requested_changes'
    comments: str
  ) -> WorkflowStatus
  
  * Validate approver has authority for current step
  * Record action in approval_actions
  * If approved: move to next step or complete
  * If rejected: notify requester, allow resubmission
  * If all steps complete: update clause status to 'legal_approved'
  * Send notifications at each state change

- get_pending_approvals(user_id: UUID) -> List[ApprovalRequest]
  * Return all pending approvals assigned to this user
  * Group by priority and age
  * Include contract/clause preview

- auto_escalate_stale_approvals()
  * Celery periodic task (runs daily)
  * Find approvals pending > 3 days
  * Send reminder notifications
  * Escalate to manager if > 7 days

BUSINESS RULES:
- New clauses: Require legal_reviewer → compliance_officer → senior_legal
- Minor clause updates: Require legal_reviewer only
- Critical clauses (reimbursement, liability): Require senior_legal + compliance_director
- Template changes: Require template_manager → legal_reviewer → VP_approval

FASTAPI ROUTES:

POST   /api/clauses
       - Body: Clause data (title, text, category, metadata)
       - Returns: Created clause (status=draft)
       - Triggers: Embedding generation background task

PUT    /api/clauses/{clause_id}
       - Body: Updated clause data
       - Returns: Updated clause
       - Creates new version, preserves old version

DELETE /api/clauses/{clause_id}
       - Soft delete (status=archived)

POST   /api/clauses/search/semantic

POST   /api/clauses/{clause_id}/submit-approval
       - Initiates approval workflow
       - Returns: approval_request_id

GET    /api/clauses/{clause_id}/versions
       - Returns: Version history with diffs

POST   /api/clauses/{clause_id}/duplicate
